# HUMAN → AYYY: план браузерного переноса

Разработка: `feat/human-browser-health`; пользователь разрешил публикацию демонстрационной первой версии в `main`.  
Маршрут: `AYYY/#health`  
Исходник: приватный `i12309/human` (Go 1.26, SQLite, React/TS).  
Цель: полностью статический клиент с зашифрованным локальным хранилищем и синхронизацией только в выбранный пользователем приватный GitHub.

## Выполнено в этой ветке

- [x] Новый модуль `health/` и регистрация маршрута, пункт в каталоге/меню AYYY.
- [x] Копирование модуля при статической сборке `src/build.py`.
- [x] Раздельные шифрованные сейфы IndexedDB, WebCrypto AES-GCM/PBKDF2.
- [x] Совместимость каталогов GitHub: `family-data/` остаётся нетронутым, HUMAN пишет только `health-data/v1/vault.json`.
- [x] Пользователь сам указывает GitHub owner/repo/branch и временный fine-grained PAT; публичные репозитории блокируются.
- [x] Optimistic SHA check и ручное разрешение конфликтов через экспорт зашифрованной копии + загрузку remote.
- [x] Ручные анализы, история правок, группировка совместимых измерений, графики, референсы и CSV-импорт.
- [x] Профиль, домашние показатели, медицинские записи, препараты, дневник и небольшие документы.
- [x] Шифрованный экспорт/импорт и изоляция нескольких локальных профилей.
- [x] Тесты модели и синтаксиса в `tests/health_model.test.cjs`.
- [x] Независимый интерактивный демо-профиль на вымышленных данных (68 лабораторных результатов, 33 домашних измерения и другие записи), без записи в IndexedDB/GitHub; проверка `tests/health_demo.test.cjs`.
- [x] Промежуточные коммиты с пометкой `[skip ci]`; Action на этапе разработки не запускался.

## Остаётся, прежде чем считать перенос полным

### P0 — корректность миграции и сохранность данных
- [x] Изолированный импорт `human export-user <UUID> --output user-human.zip`: пользовательский SQLite v2, manifest, SHA256/CRC, документы, отчёт количества строк, создание отдельного шифрованного журнала. Синтетическая схема 001–016; исходный ZIP восстанавливается побайтово.
- [ ] Обратный экспорт изменений AYYY в SQLite HUMAN, обновление уже перенесённого профиля из нового снимка, крупные архивы и полноценный интерфейс дополнительных исходных разделов.
- [ ] Перенос raw DTO (values kind: quantity/censored/qualitative/range; comparator; time_precision: unknown/year/month/day/exact; source; revisions). Не преобразовывать качественные результаты и пределы в простые числа.
- [ ] Поддержать поиск/классификацию с analyte aliases, settings, favorites, unit history и provenance импортированных файлов.
- [ ] Двусторонняя корректность/идемпотентность миграции: дубликаты, частичный импорт, повторное восстановление, удалённые/черновые значения.

### P1 — эксплуатационная надёжность
- [ ] Трёхстороннее разрешение конфликтов на уровне записей, удалений, вложений; пока конфликт только блокируется.
- [ ] Раздельные зашифрованные документы и метаданные (вместо единого vault snapshot), поддержка больших файлов, лимитов API, восстановления целостности.
- [x] Атомарная защита IndexedDB от конкурентных записей, многовкладочная блокировка, перезагрузка, ошибка квоты с повтором и локальная запись при отсутствии сети. Проверена отмена запоздавших операций при смене сессии.
- [ ] Расширенная проверка очистки данных и аварийного закрытия процесса во всех целевых браузерах.
- [ ] Браузерная E2E матрица: Chromium/Firefox/WebKit, desktop/phone; XSS/CSP/a11y.
- [ ] Независимые резервные копии (GitHub не заменяет backup), проверка restore и ротации ключа/фразы.
- [ ] Внешний аудит безопасности перед использованием для критичных медицинских данных.

### P2 — функции из HUMAN
- [x] Медицинская карта с частичными датами, статусами, источником сведений, подробностями аллергий/препаратов/прививок, ссылками на документы и историей правок. Проверено создание, правка, фильтры, удаление и восстановление после перезагрузки.
- [x] Эпизоды болезней и самонаблюдения: неопределённость, подтверждение, завершение, отложенное уточнение, связи с измерениями/медкартой и история. Проверены календарные дни и DST, удаление и перезагрузка.
- [x] Учёт приёмов/пропусков препаратов, разовые/ежедневные расписания, действия и история, колокольчик и явное включение локальных уведомлений при открытом разблокированном журнале. Проверены DST, версия, изоляция, перезагрузка и миграция исходного care.
- [x] Локальный импорт PDF с текстовым слоем/XLSX/CSV с выбором листа, сопоставлением колонок, редактируемым черновиком, подтверждением и provenance; просмотр PDF. Проверен синтетический импорт и восстановление вложений после перезагрузки.
- [ ] OCR сканов, расширенные макеты таблиц (даты в колонках), пакетная очередь импорта и лимиты крупных вложений.
- [ ] Полноценные дневники питания и активности с агрегатами.
- [ ] Генетические findings (без автоматической клинической интерпретации).
- [ ] Внешние устройства/сервисы Samsung Health, Xiaomi и ИИ только по отдельному согласию.
- [ ] Обновление и адаптация текущего дизайна HUMAN к AYYY, в том числе плотность экранов.

## Правила для следующих этапов

1. Ни один коммит в AYYY не содержит настоящие медицинские данные, токены, фразы или SQLite.
2. Основной перенос остаётся в рабочей ветке. Публикация демо и первых статических функций в `main` разрешена владельцем; исходный HUMAN остаётся без изменений.
3. Не запускать Actions на каждом промежуточном коммите; публикацию и проверки выполнять после завершения содержательного блока.
4. Не утверждать полноту переноса, пока не реализованы миграция v2, тесты точности дат/значений и восстановление.
5. Не менять `family-data` и поведение модуля GEN ради HUMAN.
