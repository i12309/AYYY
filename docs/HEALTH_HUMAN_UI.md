# Интерфейс здоровья HUMAN в AYYY

## Актуальная модель

По уточнению пользователя данные загружаются заново. Журнал принимает новые CSV/XLSX/PDF/PNG/JPEG и восстанавливает зашифрованные копии текущего формата `.human`.

Исходник оформления — текущий `C:\CODE\human`. Используются его CSS shell, analyses, medical, health, care и diary; адаптация находится в `health/human-adapter.css`. Все стили ограничены отдельным iframe. Главная страница портала и расположение AYYY/HUMAN сохранены.

В Chromium сверены 12 общих разделов на 390 и 1440 px: обзор, анализы, показатели, медкарта, приёмы, рекомендации, питание, активность, генетика, профиль, документы и история. Сравнение сделано после входа в отдельную сборку HUMAN из `9f970dd` с синтетической базой. Её `index-BCj7LWDO.js` и `index-lN7yGkzr.css` побайтно совпали с файлами работающего экземпляра на `192.168.3.161:8000`. На самом сервере открывался только экран входа. Различия хранилища, настроек и дополнительные разделы браузерной версии сохранены.

## Рабочие разделы

Анализы группируются только при совместимых показателе/единице/материале/методе. Исходные результаты, пределы, качественные значения и точность даты сохраняются. Общие референсы и избранное относятся к группе и не подменяют норму исходного бланка. Список показывает по 50 групп и пересчитывает результаты и среднее за выбранный период. Частичная дата включается при пересечении с периодом, неизвестная дата видна в общем списке. При открытии показателя доступна вся его история. Импорт новых файлов проходит сопоставление колонок и подтверждение редактируемого черновика; сканы распознаются в браузере. Исходник связан с результатом и доступен для просмотра/скачивания.

При импорте HUMAN проверяет возможные совпадения измерений между файлами, включая разные форматы. Учитываются точность даты, результат и известные сведения из бланка. В отмеченной строке можно сохранить отдельное измерение или связать исходник с выбранной записью. Связанные файлы и координаты видны на странице измерения и сохраняются в зашифрованном журнале.

Импорт открывается отдельной страницей внутри журнала. Начать можно из «Анализов», из формы нового анализа или из сохранённого документа. Выбор файлов, папки и камеры доступен и при открытом черновике. Новые файлы добавляются в ту же очередь. Если перейти в другой раздел, «Продолжить импорт» возвращает открытый черновик с правками до блокировки журнала. Чтобы продолжить после блокировки или перезагрузки, сохраните черновик на устройстве.

Вкладки над формой переключают бланки и показывают статус каждого файла. Стрелки, Home и End перемещают фокус, Enter или пробел открывают файл. При переключении правки и решения по совпадениям сохраняются в текущем сеансе. Если этот файл уже был сохранён в зашифрованном черновике, при переключении его правки также записываются на устройство.

При проверке выберите показатель в списке. Редактор показывает исходный фрагмент, основные поля и раскрывающийся раздел дополнительных сведений. Для XLSX во фрагменте видны адреса ячеек и сохранённые формулы. Ввод в редакторе оставляет исходный фрагмент неизменным. После частичного сохранения редактор открывает первую выбранную строку с ошибкой или следующую незавершённую строку. Сохранённые строки можно раскрыть и просмотреть.

Для числового результата без единицы черновик предлагает единицу из настроек или из подтверждённых измерений того же показателя с совместимым материалом и методом. При нескольких вариантах из истории пользователь выбирает один. Единственный вариант виден в поле с подписью об источнике. Его можно снять или заменить. Сохранённый результат содержит исходную единицу и основание подстановки отдельно. Если настройка или измерение, из которого взята единица, изменились, перед записью потребуется новый выбор.

Колонку с референсным текстом можно сопоставить как «Условия референса из бланка». Исходная формулировка сохраняется отдельно от правок. Однозначный интервал заполняет числовые границы, если они не были заданы отдельными колонками или отредактированы вручную. Условные диапазоны и пороги доступны в записи и в локальном снимке для рецензии как текст. Без числовых границ результат остаётся без оценки по референсу.

«Выбрать готовые» отмечает валидные строки таблицы без известных совпадений в журнале. Ручные и распознанные строки отмечаются по одной после сверки с бланком. Подтверждение записывает готовые результаты. Строки с ошибками или неразрешёнными совпадениями остаются доступными для правки. После частичного подтверждения видно число сохранённых и оставшихся строк.

«Импорт папки» добавляет поддерживаемые файлы из выбранной папки и её подпапок. В очереди видны относительные пути, чтобы различать одноимённые бланки. Путь сохраняется только в зашифрованном черновике. Перед записью результатов подтвердите их принадлежность открытому профилю для каждого файла. При повторном открытии сохранённого черновика подтвердите принадлежность заново.

«Сохранить черновик» сохраняет очередь, исходные файлы, сопоставление колонок, правки и отметки строк. Чтобы вернуться к ней, откройте «Анализы» → «Открыть черновик импорта». На устройстве хранится одна сохранённая очередь на журнал. Частичное подтверждение обновляет правки в ранее сохранённом черновике, а полное исключает из очереди завершённый файл. При повторном открытии журнал проверяет исходные координаты уже сохранённых строк.

В анализах «Снять фото бланка» открывает системный выбор изображения с запросом задней камеры. Форма добавления документа содержит такую же кнопку. В импорте можно открыть оригинал изображения или выбранную страницу PDF, ввести результат вручную и явно отметить строку для записи. У ручного результата сохраняются файл, страница PDF и способ ввода. Если распознавание изображения недоступно, исходник доступен для просмотра и ручного ввода.

Документы ищутся по исходному имени и названию в журнале. Список показывает по 50 файлов. В просмотре можно открыть сведения о файле, включая SHA-256, скачать оригинал или нажать «Разобрать анализы» для PDF, XLSX, CSV, PNG и JPEG. Результаты связываются с выбранным документом, в том числе после возобновления черновика.

Генетика использует карточки и поля текущих `genetics/GeneticsPage.tsx`, `FindingForm.tsx` и `app/AppDialogs.tsx`. Новые ручные записи содержат результат, поставщика, категорию, метку отчёта, исследование, точность даты, гены, варианты, исходное пояснение, версию метода, URL и документ-источник. Карточки поддерживают поиск по названию/поставщику, категории и страницы по 50 записей. Общий поиск находит также исходные поля и открывает подробности. Исправления сохраняют прежние факты. Неизвестный день/месяц не дополняется; отсутствующие варианты, сборка, strand и генотип не восстанавливаются. Метка «По отчёту: внимание» остаётся сведением поставщика, а не вычисленным заключением. Вложения VCF/JSON показываются как текст и скачиваются побайтово; автоматического разбора генома или клинических выводов нет. Из документа можно вернуться к результату. Внешняя ссылка появляется только после проверки HTTP(S) и не открывается автоматически.

В показателях есть виды домашних измерений, история, выбранная запись и график; давление вводится двумя числовыми полями и отображается двумя линиями с одной клавиатурной остановкой на пару. При смене вида несохранённого измерения прежние числа очищаются; вид сохранённой записи не меняется. После сохранения открываются запись и её единица. График имеет высоту 195 px и адаптивную ширину, не уменьшает подписи до нечитаемого размера. История и график разбиты по 200 записям, total и переход к более ранним остаются видимыми; единицы глюкозы не смешиваются и не пересчитываются. У взрослого основное поле роста находится в профиле, новая вкладка роста скрыта; прежняя запись доступна для исправления и не меняет основной рост. Без даты рождения возраст не предполагается. Эпизод содержит собственное описание/сведения врача и явное состояние. Истечение подтверждения не означает выздоровления, отсрочка не подтверждает болезнь. Подтверждение/завершение/отсрочка 1/3/7 календарных дней сохраняются в истории; ручное неоднозначное время требует UTC offset.

Медкарта включает аллергии, препараты/добавки, прививки, состояния, операции и другие сведения. Сохраняются подробные факты, статус, источник сведений, точность начала/окончания, ссылки на документ/эпизод и история исправлений.

Приём/пропуск препарата и напоминание — разные сущности. Фактическое событие не может быть будущим и не меняет плановую дозу. Напоминания имеют свою зону и разовое/ежедневное расписание, паузу, выполнение, пропуск и отсрочку 15/60/180 минут. Выполнение не создаёт приём. DST: отсутствующее ежедневное время пропускается, повторяющееся используется один раз в ранний момент. Браузерные уведомления включаются явно, содержат только общий текст и работают при открытом разблокированном журнале.

Питание и активность — отдельные компактные разделы, как в HUMAN. Еда хранит точное время в зоне профиля и значения для всей порции; пустое число остаётся null, введённый ноль остаётся нулём. Итог показывает только известную сумму и число заполненных записей; поиск/вся история не меняют итог выбранного дня. Активность хранит одну запись на день: шаги, сон/упражнения в минутах, вид нагрузки и заметки. График пропускает неизвестные значения и открывает день с клавиатуры. История, исправления, удаление и явное повторное создание дня сохраняются. Формы встроены в страницу, незавершённый ввод остаётся при фильтрации. Смена даты обрабатывает input/change без повторного закрытия редактора: исправлен первый клик добавления активности в WebKit. События от снятых с экрана полей не меняют новый раздел.

Профиль повторяет карточки текущего `profile/ProfilePage.tsx`: личные сведения, данные, медкарта, документы, приёмы и история. Форма проверяет обязательное имя, дату рождения, рост и зону. Возраст учитывает день рождения в зоне профиля. Для возраста до 20 лет доступна история роста в показателях; скрытый основной рост не затирается.

История использует текущие действия, а не даты обследований: добавление, исправление, удаление, импорт, профиль, восстановление и смену фразы. Фильтры/поиск и страницы по 50 событий; переход к исходной записи или к сохранённому событию удаления. Выполнение напоминания остаётся действием напоминания и не создаёт приём. Старые снимки не реконструируются.

Рекомендации повторяют текущие `recommendations/RecommendationsPage.tsx`, `IntakeForm.tsx`, `ReportView.tsx` и CSS HUMAN. Анкета содержит 10 свободных вопросов; пустой ответ остаётся неизвестным, версии сохраняются. История открывает именно выбранную прежнюю версию. Пакет готовится явно, с заданием и ограниченными выборками/total, SHA-256, без имени/даты рождения, генетики, оригиналов файлов и их метаданных. Клинические поля, точность времени/дат и неизвестные числа сохраняются. Свободный текст требует просмотра владельцем. Новый пакет имеет схему `ayyy-human-review/1`, а не формат серверной БД; конвертации старых моделей нет. [Формат пакета и рецензии](../health/RECOMMENDATIONS.md).

Рецензия загружается JSON до 900 КБ, проверяется на свой context/request/prompt, IDs анализов и публичные HTTPS-источники. Повтор request_id не дублирует текст; другое содержимое с ним отклоняется. Оценка/питание/движение/контроль, автор/метод/дата, ограничения, draft/read/archived, предыдущие состояния и исходный снимок сохраняются отдельно от клинических данных. Изменённые данные помечают рецензию устаревшей. Ссылка на анализ показывает сначала его сведения из снимка, даже после удаления текущего анализа. HTML/Markdown не исполняются, сеть не вызывается. Генератора медицинских рекомендаций нет, как и в текущем исходном HUMAN.

## Сохранение и GitHub

Открытые данные существуют в памяти. IndexedDB хранит зашифрованные метаданные и файлы в отдельных таблицах. GitHub получает журнал и блоки AES-GCM в `health-data/v2/` одним обновлением ветки с проверкой версии. Фраза и токен хранятся в памяти вкладки.

Черновик импорта шифруется текущим ключом журнала в отдельной таблице IndexedDB. Он доступен на устройстве, где был сохранён. Резервная копия и синхронизация содержат подтверждённые записи и вложения. Смена фразы на этом устройстве перешифровывает черновик в одной транзакции с журналом и документами. При удалении локальной копии удаляется и её черновик.

При уходе со страницы HUMAN блокирует журнал, очищает форму и отзывает URL предпросмотра. При возврате из истории браузера он перечитывает локальное хранилище и запрашивает фразу доступа. Это проверено при реальном восстановлении из памяти в Chromium и синтетическими событиями в Chromium, Firefox и WebKit.

Замена и отключение GitHub-токена отменяют запросы старого подключения. Перед отправкой и перед публикацией ветки HUMAN проверяет приватность и идентификатор репозитория. GitHub API не объединяет смену видимости и обновление ветки в одну транзакцию, поэтому репозиторий должен оставаться приватным. [Метаданные репозитория](https://docs.github.com/en/rest/repos/repos#get-a-repository) · [Обновление Git-ссылки](https://docs.github.com/en/rest/git/refs#update-a-reference)

Одна транзакция IndexedDB проверяет ожидаемую версию и записывает метаданные вместе с вложениями. При исчерпании квоты браузер откатывает транзакцию и оставляет форму для повторной попытки. Без сети локальные правки ожидают отправки. При конфликте HUMAN сравнивает обе копии с общей исходной версией. Пользователь выбирает вариант только для спорных записей.

Для локальной записи и удаления запрашивается режим `durability: 'strict'`. При удалении HUMAN проверяет, совпадает ли журнал со скачанной копией, и после записи уведомляет соседние вкладки. `python -X utf8 tests/health_crash_browser.py` принудительно завершает отдельный Chromium с временным профилем и проверяет четыре операции до и после фиксации. [Спецификация IndexedDB](https://w3c.github.io/IndexedDB/#transaction-durability)

Текущий backup сначала расшифровывается и проверяется фразой, затем показывает состав для подтверждения. Он не записывается при неверной фразе, повреждении или отказе хранилища. Повторное восстановление создаёт отдельный журнал, сохраняя исходный; подключение GitHub не переносится автоматически. Смена фразы повторно подтверждает текущую, генерирует новую соль/ключ/IV и атомарно сохраняет все записи и вложения. Ошибка оставляет прежний архив; блокировка отменяет ещё не записанное шифрование. Другие вкладки закрываются; старый backup продолжает открываться своей прежней фразой.

Живой тест TEST_TREE использует отдельную временную ветку с синтетическими зашифрованными данными. Проверены транспорт, полное UI-сохранение расписания, восстановление вторым браузером и конфликт, сохраняющий локальный черновик и remote. Дополнительно проверены смена фразы через UI, синхронизация нового envelope и открытие третьим независимым браузером с новой фразой. Анкета, снимок и отдельная рецензия также восстановлены вторым браузером и доступны в UI третьего после смены фразы. Токен взят из `gh` только в память, тестовая ветка удаляется в finally.

Используются отдельные браузерные контексты и только синтетические данные. Локальные тесты блокируют внешние запросы; живой тест разрешает только API GitHub. Проверки охватывают точность, DST, неизвестные числа, сохранение/перезагрузку, профили, конкурентную запись, XSS в заметках, клавиатуру и ширины 360–1920 px. Базовая матрица Chromium/Firefox/WebKit — 270 проверок 14 экранов на 360/768/1440 px: навигация, подписи полей, клавиатура, отсутствие переполнений/ошибок/сети. Профиль/история/копии/смена фразы — по 49 сценариев в каждом движке. Рекомендации — по 42 сценария в каждом из трёх движков. Для всех сценарных наборов движок выбирает `$env:HEALTH_BROWSER='firefox'` или `'webkit'`, по умолчанию Chromium. Наполненные формы и графики проверены отдельными сценариями в каждом движке. runner запускает 13 наборов: общий интерфейс (116), каталог и импорт анализов, медкарта (35), эпизоды (27), измерения (49), приёмы/напоминания (36), питание/активность (45), генетика (42), документы (87), зашифрованные черновики импорта, хранилище (26), профиль/копии (49), рекомендации (42). `--engine firefox` / `--engine webkit` выбирает движок; повторяемый `--suite` ограничивает запуск нужными наборами. Синтетические снимки сохраняются только Chromium, чтобы параллельные прогоны не перезаписывали друг друга. Проверки удаления дожидаются подтверждённого изменения UI, а не предполагают синхронную запись IndexedDB.
