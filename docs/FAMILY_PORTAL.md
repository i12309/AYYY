# Родословная GEN внутри AYYY

## Что запущено

AYYY — статический портал. GEN встроен в маршрут `#family` с полноэкранным
браузерным React-приложением `family/` (без Python, Docker, FastAPI или своей БД).
Исходники приложения лежат в `family-app/`, собранный дистрибутив в `family/`.

В приватном GEN существующая серверная версия не изменялась.

Готово:
- Перенесён исходный React-интерфейс GEN, включая семейный граф на React Flow/Dagre,
  таблицу, карту поколений, карточки, фильтры и редактирование персон и семей.
- JSON-схема версии 1, проверка ID, ссылок родства и циклов. Неизвестные GEDCOM
  структуры в `_raw` и `metadata` не удаляются при обычных изменениях.
- IndexedDB: отдельные деревья и медиа, транзакции операций, восстановление после
  закрытия и повторного открытия вкладки.
- Импорт полного `tree.json` из прежнего GEN и GEDCOM 5.5.1/7; экспорт GEDCOM, JSON и ZIP с локальными медиа и исходным `original.ged`.
- Подключение собственного **приватного** GitHub-репозитория по fine-grained PAT
  с разрешением Contents: Read and write; токен только в памяти открытой вкладки.
- Ручная синхронизация JSON, генерируемого GEDCOM, исходного GEDCOM и фотографий/PDF в одном Git-коммите.
  Нет force push. Проверяются SHA исходного дерева и актуальный HEAD ветки;
  удалённые изменения блокируют запись с предупреждением.
- Список доступных деревьев в GitHub и восстановление JSON с медиа
  на новом устройстве. Существующее локальное дерево с тем же ID не затирается.
- Публичный GitHub-репозиторий запрещён для сохранения семейных данных.
- Две темы оформления: Classic GEN и AYYY; выбор сохраняется в браузере.

## Пользовательский сценарий

1. Откройте `https://i12309.github.io/AYYY/#family`.
2. Создайте дерево или импортируйте `.ged`, `.gedcom` или `tree.json` из GEN. Для теста есть
   пример с вымышленными людьми.
3. Работайте локально; изменения сохраняются в браузере.
4. Создайте **приватный** репозиторий GitHub с веткой `main` (при создании
   инициализируйте README, чтобы появилась ветка).
5. Создайте fine-grained Personal Access Token, ограниченный этим репозиторием:
   Contents — Read and write. Не вводите этот ключ на чужих сайтах.
6. Откройте «Локальное дерево» / «Хранение семейного архива», введите
   `owner/repository`, ветку, токен и нажмите «Синхронизировать».
7. На другом устройстве: «Открыть из GitHub» → тот же репозиторий и токен →
   выбрать дерево. Будут получены JSON и связанные медиа.
8. После локальных изменений повторно нажимайте «Синхронизировать».
   **Автоматической фоновой отправки пока нет**. Для дополнительной защиты
   регулярно экспортируйте ZIP.

Примечание: можно открыть архив старого приватного `i12309/GEN`, так как данные
расположены в `family-data/trees/<slug>/`. Если серверный GEN продолжает писать
в этот репозиторий, его изменение будет считаться конфликтом. Для самостоятельных
пользователей удобнее отдельный репозиторий данных.

## Архитектура

- `family-app/src/lib/browserModel.ts` — создание персон, семей, фильтрация полей,
  проверки ссылок, циклов и номеров ревизий.
- `family-app/src/lib/browserStore.ts` — IndexedDB, транзакции, локальные медиа.
- `family-app/src/lib/browserBackend.ts` — аналог части прежнего REST API,
  вызываемый непосредственно React-компонентами.
- `family-app/src/lib/githubSync.ts` — GitHub REST/Git Data API, ручная
  синхронизация и восстановление, проверка приватности и конфликтов.
- `family-app/src/lib/browserArchive.ts` — загрузка JSON/ZIP с локальными медиа.
- `family-app/src/components/GitHubImportDialog.tsx` — выбор личного репозитория
  и дерева для восстановления.
- `src/family-route.js` — маршрут и iframe в статическом портале AYYY.

## Сборка и проверки

~~~sh
npm ci --prefix family-app
npm run build --prefix family-app
node tests/model.test.cjs --fixture
node --experimental-strip-types --test tests/family-*.test.cjs
# после установки Chromium для Playwright:
node family-app/e2e/smoke.mjs
node family-app/e2e/github.mjs
node family-app/e2e/gedcom.mjs
python3 src/build.py
~~~

Workflow `.github/workflows/build-family.yml` проверяет TypeScript,
18 модульных GEDCOM-тестов, тесты остальных сервисов и три браузерных smoke-сценария, включая имитацию приватного
GitHub и восстановления на втором устройстве. Затем он фиксирует скомпилированные
файлы в `family/`, чтобы GitHub Pages не требовался npm в момент просмотра.

## Ещё не готово

1. Расширенная дифференциальная проверка экспорта с Python GEN и редких вариантов
   импорта из сторонних программ (описана в [FAMILY_TODO.md](FAMILY_TODO.md)).
2. Импорт ZIP/медиа с локального компьютера: один JSON-файл не несёт
   бинарные фотографии. Экспорт ZIP уже готов.
3. Продвинутое разрешение конфликтов, сравнение поколений и слияние изменений.
   Сейчас конфликты блокируют опасную запись, не сливаются автоматически.
4. Расширенная проверка больших деревьев, телефонов, планшетов и accessibility.
5. Поддержка OAuth/GitHub App без ручного токена (потребует небольшой серверной
   функции обмена кода, сам GEN останется браузерным).
6. Доработка и визуальная проверка второй темы AYYY; Classic GEN сохранена.

**Безопасность:** папка `family-data/` и реальные личные деревья из приватного
GEN **не копируются в публичный репозиторий AYYY**. Код и демонстрационные данные
с искусственными персонажами — разные сущности.



## Совместимость, реальный GitHub и большие архивы

В приватном `TEST_TREE` запущены независимые проверки на синтетических данных:
- [Python GEN vs JS GEDCOM](https://github.com/i12309/TEST_TREE/actions/runs/42698950753):
  14 файлов, 58 сравнений, 0 расхождений по сохранённой семантике.
- [Настоящий GitHub API из Chromium](https://github.com/i12309/TEST_TREE/actions/runs/42699865413):
  6/6 проверок. Для CI использован временный GitHub Actions token,
  не пользовательский PAT; ветка QA удалена.
- [Нагрузочный тест 1000–30000 человек](https://github.com/i12309/TEST_TREE/actions/runs/42700824556):
  все сценарии прошли. Итоги и оговорки — [FAMILY_PERFORMANCE.md](FAMILY_PERFORMANCE.md).

При >2500 человек GEN открывает граф ближайших родственников, чтобы не
загружать браузер раскладкой всех узлов. Полный список людей доступен
во вкладке «Таблица»; осознанное построение полного графа сопровождается
предупреждением.
