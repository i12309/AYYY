# Родословная в AYYY — первая итерация

## Цель

Перенести редактор из приватного GEN в статический портал AYYY, сохранив полноценный
React-интерфейс, граф и карту поколений. Работать без Python, Docker и собственного
серверного хранилища. Данные каждого пользователя должны находиться в его браузере
и, после подключения, в отдельном личном приватном GitHub-репозитории.

## Размещение

- \`#family\` — маршрут портала AYYY, отдельный полноэкранный iframe того же origin.
- \`family-app/\` — исходный React + TypeScript из GEN (44 перенесённых файла).
- \`family/\` — собираемые Vite статические файлы, публикуемые на GitHub Pages.
- \`family-app/src/lib/browserModel.ts\` — проверка связей и операции над JSON.
- \`family-app/src/lib/browserStore.ts\` — IndexedDB с атомарными транзакциями.
- \`family-app/src/lib/browserBackend.ts\` — API-совместимый адаптер компонентов GEN.
- \`family-app/src/lib/browserArchive.ts\` — локальный JSON/ZIP с медиа.
- \`tests/family-model.test.cjs\` — тесты родства, сохранения неизвестных полей и сборки.

Команда: \`npm ci --prefix family-app && npm run build --prefix family-app\`.
После сборки откройте AYYY через локальный HTTP-сервер и маршрут \`#family\`.
Workflow \`.github/workflows/build-family.yml\` собирает React и коммитит
скомпилированные файлы в каталог \`family/\` при изменениях источников.

## Что работает в первой итерации

- Существующие React-экраны GEN, граф, таблица и карта поколений.
- Создание/редактирование людей и семей, добавление родственников.
- Проверка на циклы, уникальность идентификаторов и существование связей.
- Сохранение нескольких деревьев в IndexedDB, ревизии и транзакции внутри браузера.
- Импорт существующего \`tree.json\` GEN **без выбрасывания \`_raw\` и метаданных**.
- Экспорт JSON и ZIP с локально сохранёнными изображениями и PDF.
- Загрузка новых фотографий/файлов с локальным сохранением.

## Ограничения и дальнейшая работа

1. GEDCOM 5.5.1 и 7: необходимо портировать \`api/gen/gedcom.py\` с сохранением
   неизвестных структур; пока импорт/экспорт .ged отключён, чтобы не портить данные.
2. Из \`tree.json\` невозможно получить бинарные фотографии: нужен импорт ZIP
   или загрузка \`media/\` из GitHub.
3. Встроенный прежний UI синхронизации с сервером будет заменён на GitHub Contents/
   Git Data API и кнопку подключения личного репозитория.
4. При одновременной работе нескольких устройств требуется блокировка перезаписи
   по SHA и отдельное разрешение конфликтов. Нельзя выполнять force push.
5. Нужны браузерные сценарии (в том числе на больших деревьях), проверки мобильной
   вёрстки и соответствия GEN после переноса.
6. Токены GitHub нельзя сохранять в \`localStorage\`, репозитории или логах.
7. Случайную публикацию живых персональных генеалогических данных в AYYY
   запрещаем: папка \`family-data/\` из приватного GEN не копируется.

## Критерий следующей приёмки

Новый пользователь создаёт дерево без GitHub, редактирует родство, перезагружает
страницу без потери данных, экспортирует ZIP, затем подключает приватный репозиторий,
синхронизирует и восстанавливает данные на другом компьютере без Python.
