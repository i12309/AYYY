# OBERON — заметки Markdown в AYYY

OBERON открывается через `#oberon` в портале и напрямую из `oberon/`. На стартовом экране находятся логотип, список подключённых репозиториев и отдельная карточка демонстрационного проекта. Ссылка `#oberon/demo` открывает демо сразу.

## Пространства и файлы

Каждая карточка соответствует одной паре «репозиторий + ветка». Хранилище заметок находится в корневой папке `OBERON/`. Подпапки и файлы Markdown отражаются в дереве редактора. Один репозиторий можно использовать также для других сервисов AYYY: синхронизация OBERON изменяет только относящиеся к нему пути.

Демонстрационный проект имеет постоянный идентификатор. Повторное открытие возвращает пользователя в тот же проект и не создаёт очередную копию. Его данные и изменения хранятся на текущем устройстве и не отправляются в GitHub.

## Подключение GitHub

Для подключения указываются адрес репозитория и ветка. Для чтения открытого репозитория токен не обязателен. Для записи или доступа к приватному репозиторию нужен GitHub Personal Access Token с правами Contents на выбранный репозиторий.

Токен остаётся в памяти открытой страницы. Переключение между пространствами в рамках страницы сохраняет соединение; после перезагрузки токен требуется ввести снова. Токен не записывается в IndexedDB, localStorage, экспорт заметок или репозиторий.

Репозиторий необходимо предварительно создать и инициализировать на GitHub, например файлом README. Папка `OBERON/` может отсутствовать: она появляется при первой записи заметки. Git не хранит пустые папки, поэтому для них используется файл `.gitkeep`.

## Сохранение и конфликты

Локальные черновики разделены по пространствам и сохраняются в IndexedDB. Подключённое пространство синхронизируется после паузы в редактировании; в интерфейсе также доступна ручная синхронизация. Статус различает локальное сохранение и запись в GitHub.

Перед отправкой сравниваются исходная версия, локальные изменения и текущее состояние ветки GitHub. Изменения разных файлов объединяются. Если один и тот же путь изменён с обеих сторон, пользователь выбирает нужную версию. Обновление ветки выполняется без принудительной перезаписи.

Сохранение нескольких файлов использует единый Git-коммит. Посторонние файлы репозитория и неподдерживаемые вложения сохраняются. Изменения Markdown, переименование и перенос заметок остаются обычными операциями над файлами.

## Статическое приложение

- `src/oberon-route.js` регистрирует маршрут портала и открывает отдельное приложение в iframe на всю рабочую область.
- `oberon/` содержит HTML, CSS, JavaScript и SVG-оформление. Приложение не требует отдельного сервера.
- `src/build.py` включает маршрут и копирует папку OBERON при сборке как с внешними ресурсами, так и с `--inline`.
- Старый маршрут `#notes` остаётся удалённым; новый сервис имеет собственный идентификатор `oberon`.

Проверки интеграции портала: `node --test tests/oberon_portal.test.cjs`. Проверки транспорта GitHub: `node --test tests/oberon_github.test.cjs`.

## Разработка и проверки

После изменения приложения выполните `python3 oberon/build.py`: команда
обновляет версии CSS/JS в HTML и версию iframe в маршруте. Затем выполните
`python3 src/build.py` и включите обновлённый корневой `index.html` в коммит.
Все ресурсы локальные; CDN, npm и отдельный backend для OBERON не требуются.

```sh
node --test tests/oberon_*.test.cjs
python3 tests/weather_build_test.py
```

Проверки транспорта используют моделируемые ответы GitHub API. Тесты координатора
покрывают изменения во время запроса, конфликт вкладок, отложенный выбор версии
и сохранение последних нажатий перед сменой пространства. Запись в настоящий
репозиторий требует токена пользователя и проверяется отдельно.

## Возможности и границы первой версии

Редактор поддерживает заголовки, списки, задачи, таблицы, блоки кода, цитаты,
метки, `[[ссылки]]` и ссылки на `.md`. Доступны оглавление, обратные ссылки,
граф, поиск по тексту, избранное, импорт `.md`, экспорт заметки или ZIP с папкой
`OBERON/`, дневная заметка, переименование и перенос файлов. Есть режимы чтения,
редактирования и просмотра рядом, светлая и тёмная темы.

Это самостоятельный редактор, без системы плагинов Obsidian. Произвольный HTML
не исполняется; внешние и локальные вложения сейчас не отображаются как картинки.
Неподдерживаемые файлы в GitHub сохраняются без изменения. Для синхронизации
поддерживаются до 1000 заметок, до 2 МиБ на файл и до 32 МиБ Markdown в пространстве.
Пустой, ещё не инициализированный Git-репозиторий необходимо сначала создать с README.

Автосинхронизация работает при открытой странице, после двух секунд покоя.
Список подключений и локальные черновики относятся к текущему браузеру. На другом
устройстве нужно подключить тот же репозиторий и ветку; заметки загрузятся из GitHub.
