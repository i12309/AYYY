# AYYY: интеграции без собственного backend

Дата: 6 ноября 2026 г. Исходники: `src/pages.js`, `src/data.js`, `src/connected.js`, `src/gmail.js`.
Портал остаётся статическим HTML/JavaScript и размещается на GitHub Pages.

## Посылки · 17TRACK

Встроенный виджет 17TRACK вызывается через официальный скрипт `https://www.17track.net/externalcall.js`, метод `YQV5.trackSingle`. Он не требует собственного API-ключа. Чтобы скрипт не выполнялся в том же контексте, что и Gmail, он загружается внутри `iframe srcdoc sandbox="allow-scripts allow-forms allow-popups allow-popups-to-escape-sandbox"` без `allow-same-origin`. Пользователь сам нажимает кнопку отслеживания, после чего трек-номер передаётся поставщику. Пользовательский список номеров хранится в localStorage и не запрашивает статусы автоматически.

Сервис не опрашивает API в фоне, не показывает уведомлений о смене статуса. У 17TRACK есть ограниченные бесплатные квоты API, но самостоятельная интеграция API и вебхуки для GitHub Pages не подходят без защищённого посредника. На случай, если вложенный виджет заблокирован, сохранены ссылки на сам 17TRACK и сайты перевозчиков.

Документация: https://www.17track.net/en/widget и https://api.17track.net/en/doc

## Финансы · TradingView

Демонстрационные рыночные значения и нарисованные математикой графики удалены. Селектор показывает S&P 500 (`SP:SPX`), NASDAQ 100 (`NASDAQ:NDX`), MOEX (`MOEX:IMOEX`). График создаётся официальным `embed-widget-advanced-chart.js` внутри изолированного `iframe srcdoc sandbox` (без `allow-same-origin`), а не исполняется в основном окне сайта.

Данные и задержки определяет TradingView и правообладатель биржевой информации. Локальное приложение не читает котировки в структурированном JSON, не хранит их и не рассчитывает рыночные значения. Для недоступного инструмента есть внешние ссылки.

Документация: https://www.tradingview.com/widget-docs/widgets/charts/advanced-chart/

## ИИ · OpenAI-совместимый API

Настройка: `Адрес HTTPS API`, `модель`, личный API-ключ (если требуется). Для совместимых серверов vLLM/Ollama должна быть поддержка CORS origin портала. При отправке используется `POST /chat/completions` и `stream:true`.

Поток SSE разбирается по `data:` событиям. Поддерживается `choices[0].delta.content`, окончание `[DONE]`; отдельный JSON-ответ поддерживается как fallback. Есть остановка запроса и ограничение длины вывода. Ключ не сохраняется после перезагрузки вкладки, история текста разговора сохраняется в localStorage; при подключении собственного API сообщения отправляются указанному серверу.

По умолчанию остаётся явно обозначенный демонстрационный режим. Реальное подключение возможно только после ввода пользователем данных своей модели.

## Gmail · Google Identity Services

Реализовано чтение списков писем, открытие письма (plain text; HTML преобразуется в текст), поиск по Gmail, просмотр входящих/отправленных/избранных, отправка новых писем и локальные черновики.

Для использования:

1. Создать проект в https://console.cloud.google.com/, включить Gmail API.
2. В Google Auth Platform настроить OAuth consent screen. Для личных тестов выбрать тестовых пользователей, включая свою почту.
3. Добавить scopes `https://www.googleapis.com/auth/gmail.readonly` (ограниченный) и `https://www.googleapis.com/auth/gmail.send` (чувствительный).
4. Создать OAuth Client ID типа **Web application**. Добавить разрешённый JavaScript origin `https://i12309.github.io` (без пути `/AYYY`). Для каждого собственного домена требуется свой origin в настройках приложения.
5. В AYYY → Почта вставить Client ID, сохранить, нажать «Подключить Gmail», разрешить чтение.
6. Отправка письма запрашивает отдельное разрешение `gmail.send` и подтверждение.

В браузерном token model пароль и Client Secret не нужны. Токены хранятся **только в памяти вкладки**, не в `localStorage`. Письма тоже не сохраняются на диск через AYYY. Черновики `mailDrafts`, напротив, локальные и включены в экспорт и проверяемый импорт резервной копии. Отправка сообщения не происходит при сохранении черновика.

Для массового публичного использования потребуется пройти проверку Google OAuth; `gmail.readonly` является restricted scope. Пока нет реального Google Client ID и согласия аккаунта, готовый код не означает подтверждённое подключение.

Документация: https://developers.google.com/identity/oauth2/web/guides/use-token-model, https://developers.google.com/workspace/gmail/api/auth/scopes, https://developers.google.com/workspace/gmail/api/quickstart/js

## Поиск Google

Обычный веб-поиск оставлен как внешнее открытие Google/Яндекса/Bing/DuckDuckGo. Custom Search JSON API **закрыт для новых клиентов**, действующим доступен переходный период до 1 января 2027 года. Для новых Programmable Search Engine с января 2026 разрешён поиск только по ограниченным 50 доменам, не по всему интернету.

Справка: https://developers.google.com/custom-search/v1/overview и https://support.google.com/programmable-search/answer/12397162

## Безопасность и ограничения

- Сторонние виджеты выполняются внутри `iframe sandbox` с отдельным непривилегированным origin; доступ к основному DOM, localStorage и данным Gmail не предоставляется.
- Токены Google и ключ LLM не включаются в URL или резервные копии.
- Риски: возможные блокировки sandbox сторонними API, ограничения CORS/OAuth и браузерных политик. Нужна проверка на реальном опубликованном домене.
- Успешное создание и компиляция исходников не подтверждает доступ к данным реального аккаунта: без пользовательских ключей, регистрации Google Cloud и проверки виджетов эти внешние сценарии остаются неподтверждёнными.
