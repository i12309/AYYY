# AYYY · Здоровье (HUMAN browser edition)

Статический модуль для раздела AYYY `#health`. Исходный HUMAN v2 остаётся самостоятельным Go/SQLite-приложением и **не заменён** этим прототипом целиком.

## Запуск

Откройте AYYY через HTTPS (GitHub Pages) или локальный сервер:

```bash
python3 -m http.server 8765
# http://localhost:8765/#health
```

Страница `health/index.html` запускается без Go, React, Node, Docker и внешних CDN. Встраивание — `src/health-route.js`, генератор главной страницы — `src/build.py`. Публичная версия зависит от настроенного источника GitHub Pages. Если Pages смотрит на `main`, раздел доступен по `/#health`, а демонстрация по `/#health/demo`.

## Что работает

- Несколько изолированных локальных профилей на одном устройстве.
- Создание и разблокировка индивидуального шифрованного сейфа.
- Имя, дата рождения, пол и заметки профиля.
- Ручные лабораторные анализы с источником, материалом, методом, единицей, референсами и историей исправлений.
- Группировка по названию + единице + материалу + методу; график числовых измерений и сравнение с исходным референсом каждой записи.
- Домашние показатели (давление, пульс, масса, рост, температура, глюкоза, сон, шаги).
- Медицинские сведения, список препаратов, дневники самочувствия/питания/активности/сна.
- Документы PDF/JPG/PNG/TXT/CSV до **2 МиБ на файл**: оригинальные байты сохраняются внутри зашифрованного сейфа и выгружаются на устройство. Нет OCR/автоматического PDF-импорта.
- CSV-импорт анализов с заголовками `date,name,value` или `дата,показатель,результат`; дополнительные поля: `unit,low,high,source,material,method,notes`.
- Экспорт/восстановление зашифрованного JSON.
- Ручная и отложенная автоматическая синхронизация GitHub, пока вкладка открыта и введён токен. При конфликте автоматическая перезапись запрещена.

## GitHub: личный репозиторий каждого пользователя

Каждый пользователь подключает **свой приватный** репозиторий и ветку. Допускается тот же репозиторий, который уже подключён в модуле «Родословная».

```text
<ваш-приватный-репозиторий>/
├── family-data/trees/...          # GEN, без изменений
└── health-data/v1/vault.json      # HUMAN, только ciphertext
```

Модуль проверяет, что репозиторий приватный, и использует API GitHub Contents. Fine-grained PAT: доступ к выбранному репозиторию и `Contents: Read and write`. Токен существует **только в памяти вкладки** и не записывается в IndexedDB/localStorage. Секретное слово для расшифровки — отдельное от GitHub пароля. После обновления страницы нужно снова ввести его, а для новой синхронизации — токен.

Изменения сначала шифруются и коммитятся в IndexedDB, затем отправляются в GitHub. При расхождении Git SHA локальные данные сохраняются; можно экспортировать локальный зашифрованный архив и вручную выбрать GitHub-версию. Автоматического трёхстороннего слияния медицинских данных **нет**.

**Никогда** не создавайте `health-data/` в публичном репозитории AYYY и не публикуйте персональные файлы через Pages. Даже удалённые из актуального коммита данные могут оставаться в истории Git.

## Безопасность и ограничения

- Шифрование: Web Crypto, AES-256-GCM с уникальным случайным 96-bit nonce для каждой записи; PBKDF2-SHA256, 310 000 итераций, случайная соль 128 бит. AAD привязывает содержимое к формату HUMAN.
- IndexedDB содержит зашифрованные конверты и несекретные метаданные GitHub. Открытые записи существуют только в памяти разблокированной вкладки. При закрытии iframe ключ уничтожается вместе с контекстом.
- Клиентская реализация не равноценна аудированному медицинскому сервису. XSS на том же origin, вредоносные расширения браузера и утечка токена во время сессии остаются рисками. Не подходит для регламентированного медицинского хранения без отдельного аудита.
- Один зашифрованный JSON snapshot перезаписывается при синхронизации. Для больших файлов нужна отдельная упаковка и инкрементальная модель хранения.
- Нет напоминаний в фоне, когда страница закрыта, нет обработки устройств, генетических вычислений, OCR и внешнего ИИ.
- **Импорт HUMAN v2 SQLite/export-user ZIP пока не реализован.** Нельзя выдавать этот прототип за полную миграцию с гарантией сохранности всех исходных данных, точности даты и версии лабораторных измерений. Исходные базы HUMAN не изменяются.
- Нет переноса справочника analyte aliases, исходных пакетов лабораторного импорта, версий серверных настроек референсов и истории отдельных clinical revisions.
- Статус «вне референса» не является диагнозом. Сложные типы результатов (предел измерения, неравенство, диапазон, неопределённая дата) ещё нужно переносить из Go-модели без потери семантики.

## Проверка без GitHub Actions

```bash
node --test tests/health_model.test.cjs
node --check health/crypto.js
node --check health/store.js
node --check health/github.js
node --check health/model.js
node --check health/view.js
node --check health/app.js
python3 src/build.py
```

Для приёмки необходим отдельный интерактивный браузерный прогон: создать сейф → записать анализ → закрыть/открыть → проверить неизменность исходных полей → подключить приватный GitHub → открыть на другом устройстве → проверить конфликт двух версий. Для публикации в `main` используется один итоговый коммит; проверки GitHub Actions зависят от настроенных workflows и выполняются отдельно от ручных локальных тестов.

См. `docs/HUMAN_BROWSER_PORT.md`: сначала проверенная миграция/импорт из v2 ZIP, затем точный перенос клинической предметной модели, документов и больших файлов, напоминаний, генетики, расширенных дневников и браузерная регрессия.


## Демонстрационный режим

В начальном экране нажмите **«Открыть демо без регистрации»** либо откройте `/AYYY/#health/demo`. Внутри отдельной страницы также работает `/AYYY/health/?demo=1`.

- Пример содержит **68 синтетических лабораторных результатов**, 33 домашних измерения, 4 записи медкарты, 2 лекарства, 12 дневниковых записей и 3 скачиваемых учебных файла.
- Все данные **вымышлены** и создаются заново в памяти на каждом открытии демо. Демо не записывает ничего в IndexedDB и не посылает данные в GitHub.
- Можно выбирать разделы, читать графики, добавлять и менять записи без регистрации; правки существуют только до выхода, сброса или перезагрузки страницы.
- Плашка **«ДЕМО»** видна на каждом экране. В настройках демо нет формы GitHub или экспорта, а кнопка «Выйти из демо» возвращает к настоящим локальным профилям без изменений.
- Пример автоматически появляется только по явному нажатию или ссылке с `?demo=1`; в реальный профиль никогда не подмешивается.

Проверка примера: `node --test tests/health_demo.test.cjs`.
