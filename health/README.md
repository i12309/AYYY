# Здоровье · HUMAN в AYYY

Статический браузерный модуль `AYYY/#health`, работающий в GitHub Pages без сервера. Текущий код HUMAN (`C:\CODE\human`) служит образцом оформления и функций. Главная страница портала и расположение логотипов сохранены.

Данные загружаются заново. Конвертеров, поддержки старых версий и переноса SQLite/ZIP HUMAN нет. Поддерживаются новые записи/файлы и backup текущего зашифрованного формата.

## Что работает

- Анализы: группировка, графики, точность даты, исходные результаты, референсы, классификация и избранное.
- Каталог HUMAN содержит 125 показателей. Правило названия может действовать на один файл или на весь журнал. Для строки импорта сохраняются её исходные поля и сопоставление на момент загрузки. Если в бланке пропущена единица, пользователь может выбрать её из настроек или из истории измерений с тем же материалом и методом.
- Импорт CSV, XLSX, PDF, PNG и JPEG на отдельной странице журнала. Можно выбрать файлы или папку с подпапками и добавлять файлы в открытую очередь. Для таблиц можно указать даты в строках или заголовках колонок. Даты через `/` требуют выбора порядка дня и месяца. До 100 файлов можно проверить по очереди. Для каждого бланка подтвердите принадлежность открытому профилю и сохраните готовые строки. Чтобы продолжить после перезагрузки, нажмите «Сохранить черновик», затем в разделе «Анализы» выберите «Открыть черновик импорта». Черновик и исходники хранятся зашифрованными на этом устройстве.
- Скан распознаётся в браузере на русском и английском. Для PDF автоматически распознаются до 10 страниц с изображениями без текста, остальные страницы можно распознать по одной. Сверьте распознанные поля и отметьте результаты для сохранения. Оригинал и координаты сохраняются вместе с подтверждёнными результатами.
- «Снять фото бланка» открывает системный выбор изображения. Если скан не удалось распознать, откройте оригинал в импорте и введите результат вручную. Файл и выбранная страница PDF будут доступны в записи.
- Показатели: два поля давления, точное или неизвестное время, отдельные единицы глюкозы, адаптивный график и страницы по 200 записей. Рост взрослого — в профиле, прежние измерения доступны для исправления. Явные эпизоды болезни и связи с медкартой.
- Медкарта с частичными датами, статусами и подробностями.
- Фактические приёмы/пропуски и отдельные напоминания; локальные уведомления включаются явно и работают при открытом журнале.
- Генетические записи из отчётов: категории, поля источника, частичные даты, поиск, документы и история. VCF/JSON остаются исходными файлами, без интерпретации генома.
- Питание с итогами известных значений и активность по дням с графиком, поиском и историей.
- Профиль с возрастом, ростом и зоной; карточки данных и история действий с фильтрами, поиском и переходами.
- Рекомендации: анкета, снимки текущих данных, загрузка отдельных JSON-рецензий, источники, статусы и предупреждение об устаревании. Автоматических назначений и вызовов ИИ нет. [Формат пакета/рецензии](RECOMMENDATIONS.md).
- Несколько изолированных профилей, восстановление текущих зашифрованных копий после проверки фразы и атомарная смена фразы доступа; синхронизация с приватным GitHub.

**Первое подключение GitHub:** на стартовом экране укажите приватный репозиторий, ветку и токен. Если в `health-data/v2/vault.json` уже есть журнал — он будет загружен зашифрованным, после чего понадобится его фраза доступа. Если файла ещё нет, приложение предложит создать **новую** фразу шифрования и сохранит пустой зашифрованный журнал в этом репозитории. Создавать папку вручную не нужно: GitHub создаёт её при записи файла. Поддерживаются и полностью пустые репозитории без первого коммита (при необходимости приложение создаёт служебный `.gitkeep`). Другие файлы и родословная не изменяются. Для первого сохранения нужны права токена `Contents → Read and write`; одна лишь загрузка существующего архива допускает `Read-only`.

**Фраза шифрования** защищает медицинские данные и нужна для открытия журнала на каждом устройстве. Это не GitHub-пароль и не GitHub-токен. HUMAN не сохраняет фразу, а GitHub получает только зашифрованные данные. Утраченную фразу нельзя восстановить — без неё нельзя расшифровать существующий архив.

Метаданные журнала и каждый документ шифруются отдельно с помощью WebCrypto AES-GCM/PBKDF2. Ключ, фраза и GitHub-токен остаются в памяти вкладки. В приватном репозитории журнал хранится в `health-data/v2/vault.json`, а вложения — в `health-data/v2/objects/` под хешами зашифрованных блоков. GitHub публикует полный набор одним коммитом с проверкой версии ветки.

Если журнал изменился на двух устройствах, HUMAN сравнивает их копии с последней общей версией. Независимые записи, удаления и вложения входят в объединение. Для спорных записей можно сравнить обе версии, скачать оригиналы вложений и выбрать, какую версию сохранить. При повторном изменении архива в GitHub журнал предложит сверку с новым снимком. Если общий снимок недоступен или копии зашифрованы разными фразами, локальный архив можно скачать для отдельного восстановления.

Резервная копия `.human` включает зашифрованный журнал и все вложения. При восстановлении HUMAN проверяет подлинность и контрольную сумму каждого файла, затем показывает состав копии для подтверждения. При совпадении ID создаётся отдельный журнал. Смена фразы повторно шифрует журнал и файлы в одной транзакции и закрывает другие вкладки. Ранее скачанные копии сохраняют прежнюю фразу. Новый формат рассчитан на загрузку данных заново, как согласовано для этого проекта.

Пределы хранения — 32 МиБ на файл, 128 МиБ на все вложения, 1000 документов и 28 МиБ на метаданные. Синхронизация отправляет только новые зашифрованные блоки и сохраняет локальные изменения, если GitHub ограничил частоту запросов. Для WebCrypto нужен HTTPS или localhost. Счётчик портала работает в отдельном фрейме и получает только факт открытия раздела «Здоровье».

## Демо

На стартовом экране нажмите «Открыть демо без регистрации» или перейдите в `AYYY/#health/demo`. Демо содержит только вымышленные сведения: 68 анализов, 33 измерения, эпизоды, медкарту, генетические записи, препараты, приём, напоминание, питание/активность и документы. Оно создаётся в памяти, не записывает IndexedDB и не обращается к GitHub. Все изменения исчезают после выхода/сброса/перезагрузки.

## Права токена GitHub

Для собственного приватного репозитория создайте [GitHub fine-grained token](https://github.com/settings/personal-access-tokens/new): `Repository access → Only select repositories` → выберите репозиторий. В `Repository permissions` задайте `Contents → Read and write` для синхронизации или `Contents → Read-only` при одной лишь загрузке данных. `Metadata → Read-only` включается автоматически, остальные разрешения не нужны. Нажмите `Generate token`. Разрешение `Contents: Read and write` охватывает **весь выбранный репозиторий**, а не только `health-data/`; приложение хранит токен только в памяти открытой вкладки.

Единая справка для пользователей: [`/help/github/`](../help/github/) — создание репозитория, токен, разрешения и безопасность. Ссылки доступны в обеих формах подключения HUMAN.
