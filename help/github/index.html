01 / ОБЩАЯ ИДЕЯ

Что такое GitHub и зачем он нужен?

Представьте личный шкаф для файлов в интернете. Репозиторий — это шкаф, папки — полки, а токен — временный ключ, которым вы разрешаете приложению пользоваться шкафом. GitHub также хранит историю изменений файлов.

01Ваш браузерСоздаёте или меняете заметки
→
02GitHubХранит файлы в приватном репозитории
→
03Другое устройствоОткрываете тот же репозиторий

Данные идут напрямую из браузера на GitHub через HTTPS. Отдельного сервера хранения AYYY для этих модулей нет. Синхронизация требует соединения с интернетом, а отправка изменений происходит при открытом приложении.

02 / ПОШАГОВАЯ НАСТРОЙКА

Подключение за пять шагов

Все кнопки указаны так, как они называются в интерфейсе GitHub. Иллюстрации ниже — схемы экранов для ориентирования, а не снимки ваших личных данных.

1. Репозиторий2. Токен3. Доступ4. Права5. Подключение
01 СНАЧАЛА

Создайте место для своих файлов

Откройте GitHub и нажмите New repository. Укажите любое понятное название, например my-ayyy-data.

  • Выберите Private — содержимое не будет общедоступным.
  • Отметьте Add a README file — так сразу появится ветка main.
  • Нажмите Create repository.

Если репозиторий уже есть, создавать новый необязательно. Можно использовать один приватный репозиторий для всех трёх сервисов.

Создать репозиторий на GitHub ↗
02 КЛЮЧ ДОСТУПА

Откройте создание токена

Токен — это отдельный ключ для приложения. Он не заменяет ваш пароль от GitHub.

На GitHub откройте Settings → Developer settings → Personal access tokens → Fine-grained tokens. Нажмите Generate new token.

  • Назовите токен, например AYYY Storage.
  • Для Expiration задайте срок действия, например 90 дней.
  • В Resource owner выберите свой аккаунт.
Открыть создание токена ↗
03 ВАЖНО

Ограничьте доступ одним репозиторием

В разделе Repository access выберите Only select repositories. Затем нажмите Select repositories и отметьте только свой репозиторий.

Не выбирайте All repositories без необходимости. Так вы дадите ключу больше возможностей, чем требуется.

Если используете один репозиторий для OBERON, GEN и HUMAN, достаточно выбрать его один раз.

04 САМОЕ ВАЖНОЕ

Выберите правильные разрешения

Ниже найдите Permissions → Repository permissions. Нажмите Add permissions и добавьте Contents.

  • Contents → Read and write — для создания и сохранения файлов.
  • Metadata → Read-only — добавляется автоматически, менять не нужно.
  • Других прав для обычной синхронизации не требуется.

Если вместо Read and write выбрано Read-only, чтение сработает, но при сохранении появится ошибка 403.

05 ГОТОВО

Подключите репозиторий в AYYY

Нажмите Generate token. Скопируйте полученный токен: GitHub может показать его полностью только в момент создания.

  • Вернитесь в нужный модуль AYYY.
  • Укажите репозиторий в виде username/my-ayyy-data, ветку main и вставьте токен.
  • Создайте небольшую тестовую запись и дождитесь статуса «Сохранено в GitHub» или успешной синхронизации.

Токен не нужно показывать другим людям, присылать в чат или размещать в файлах. После обновления страницы его придётся ввести заново.

03 / БЕЗОПАСНОСТЬ

Почему такой способ удобен — и что важно защитить

Доступом управляете вы: сами выбираете приватный репозиторий, назначаете минимальные права и можете отозвать токен. Но отсутствие своего сервера не означает абсолютной защиты от всех рисков.

◈

Личный репозиторий

Режим Private скрывает обычный доступ посторонних. GitHub остаётся сторонним сервисом хранения; это не сквозное шифрование.

⌘

Токен с ограничениями

Выбирайте один репозиторий и Contents: Read and write. GitHub не умеет ограничивать токен одной папкой: запись разрешена во всём выбранном репозитории.

◴

Токен только в памяти

AYYY не записывает токен в локальные файлы или браузерную базу. Он используется открытой страницей для запросов к GitHub и исчезает после перезагрузки. Защищайте устройство и браузер.

▤

Разные уровни защиты данных

OBERON сохраняет Markdown без шифрования, GEN — семейные файлы, а HUMAN шифрует журнал перед отправкой. Для первых двух приватность репозитория особенно важна.

Что не стоит делать

Не публикуйте скриншоты с токеном и не передавайте его другим. Не переводите репозиторий с личными данными в Public. Делайте отдельные резервные копии: синхронизация сама по себе не защищает от случайного удаления или повреждения данных.

04 / ПОМОЩЬ

Частые вопросы и ошибки

Ошибка 403: Resource not accessible by personal access token +

Чаще всего токен имеет только права чтения. Откройте список токенов → выберите токен → Edit → Contents: Read and write → Update. Проверьте, что нужный репозиторий выбран в Repository access. Если требуется, повторно подключите токен в AYYY.

Нужно ли создавать три разных репозитория? +

Нет. Можно использовать один приватный репозиторий: OBERON работает в OBERON/, GEN — в family-data/trees/, HUMAN — в health-data/v2/. Важно не менять чужие папки вручную без резервной копии.

Можно ли открыть данные на другом компьютере? +

Да. Подключите тот же репозиторий и ветку, введите токен и загрузите данные. Убедитесь, что на первом устройстве синхронизация действительно завершилась: локальное сохранение ещё не означает отправку на GitHub. Для HUMAN также понадобится ваша фраза доступа.

Репозиторий пустой — HUMAN не может найти журнал. Что делать? +

Это нормально при первом подключении: папку health-data/v2/ создавать вручную не нужно. На стартовой странице HUMAN нажмите «Проверить и подключить». Если журнала нет, приложение предложит создать фразу шифрования и само запишет в GitHub новый пустой зашифрованный журнал. Это работает даже в репозитории без первого коммита. Для создания нужен токен с Contents: Read and write. Родословная и другие папки не изменяются.

Зачем HUMAN просит фразу шифрования? +

Это отдельный пароль для защиты медицинских данных, а не пароль от GitHub. Он нужен для открытия журнала на этом и на других устройствах. Приложение не сохраняет его и не отправляет в GitHub. Если фраза потеряна, зашифрованный журнал восстановить нельзя. Храните фразу в надёжном менеджере паролей.

GitHub просит токен снова. Это ошибка? +

Нет. В AYYY токен хранится только в памяти открытой страницы, а не в постоянном хранилище браузера. После перезагрузки или на другом устройстве вводите его снова. Можно создать новый токен и отозвать старый.

Заметки пропадут, если отключить синхронизацию? +

Локальные данные обычно остаются в браузере, но могут исчезнуть при очистке его хранилища. Скачивайте резервные копии и периодически проверяйте, что файлы действительно есть в GitHub.

Как отключить доступ AYYY? +

Откройте настройки токенов GitHub и нажмите Delete для соответствующего токена. После отзыва старые токены перестанут работать. Сами файлы репозитория не удалятся.

Можно ли использовать публичный репозиторий? +

OBERON умеет читать публичный репозиторий без токена. Но для личных заметок, фотографий и семейных данных используйте Private. HUMAN и GEN рассчитаны на приватный репозиторий.
