# AYYY — ваш маяк в интернете

Интерактивный портал: **22 сервиса, 14 экранов, статические HTML/CSS/JavaScript и локальная иллюстрация**.
Главная — почти белая страница в мягком акварельном стиле: прежний маяк слева, шесть выбранных сервисов, поиск, погода, валюты и часы. Большое приветствие убрано. Полный список находится на отдельной странице-каталоге.
Работающие браузерные инструменты соседствуют с явно обозначенными демонстрациями будущих интеграций.

## Быстрый запуск

В корне репозитория находится готовый `index.html`. Откройте его двойным щелчком в современном браузере.
CSS, JavaScript и SVG-иконки включены в HTML. Иллюстрация маяка хранится рядом: `assets/lighthouse-watercolor.webp`; при копировании сайта сохраняйте эту папку.
Для локальных инструментов не нужны установка пакетов, сборка или подключение к CDN.

Для предсказуемой работы браузерного хранилища и сетевых запросов удобнее открыть файл через локальный HTTP-сервер:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Запускайте команду из папки с `index.html`, затем откройте <http://127.0.0.1:8000/>.
На Windows вместо `python3` можно использовать установленную команду `py` или `python`.
Это только способ локального просмотра: самому опубликованному порталу серверный runtime не требуется.
Поведение `localStorage` и некоторых браузерных API при открытии через `file://` зависит от браузера.

## Визуальная система

Главная и каталог используют почти белый фон, исходную акварельную иллюстрацию, мягкие цветовые пятна и спокойные сине-оранжевые акценты. На этих страницах нет боковой панели, служебной верхней строки и нижней панели навигации.

- На широком экране маяк закреплён относительно окна браузера. Обновление данных, прокрутка и наведение на сервисы не меняют его размер и положение.
- Луч неподвижен. Геометрия пересчитывается только при загрузке иллюстрации и изменении размеров окна или ряда сервисов.
- Большое приветствие удалено. На главной сразу видны шесть сервисов, поиск и информация на день.
- «Выбрать свои» позволяет закрепить до шести сервисов. Выбор хранится в браузере отдельно от избранного каталога.
- Поиск работает по интернету, каталогу или через ИИ. Есть выбор поисковика.
- Погода с графиком, USD/EUR/CNY и часы устройства расположены под поиском. Источники, демонстрационные и сохранённые значения подписаны; автоматических запросов нет.
- Каталог сохраняет короткий заголовок «Все сервисы», поиск, категории и избранное. Маяк расположен в отдельной левой колонке с `position: sticky`; карточки компактнее — четыре в строке на широком экране, три или две на узком.
- На телефоне маленький маяк стоит рядом с шестью сервисами; большого вводного экрана нет.
- Внутренние страницы сервисов пока используют прежнее оформление; их редизайн выполняется отдельно.
- Главная и каталог остаются белыми при любой настройке темы. Выбор светлой/тёмной темы применяется к внутренним сервисам.

| --- | --- |
| Фон | `#FFFEFC` |
| Тушь | `#203640` |
| Оранжевый | `#E77D36` |
| Морской акцент | `#3D8491` |

Иллюстрация создана по предоставленному пользователем референсу; промпт и происхождение описаны в `docs/artwork-prompt.txt`. Изображение загружается из репозитория, без обращения к Pinterest или стороннему CDN.

`Ctrl+K` открывает быстрый переход к сервисам, `/` переводит к поиску.
Кнопки, поля и диалоги доступны с клавиатуры; анимация учитывает `prefers-reduced-motion`.

Подробности и проверка: [SPLASH_REDESIGN.md](docs/SPLASH_REDESIGN.md).

## Внешние данные и подключения

### Погода и валюты

Автоматических фоновых запросов при открытии главной нет. Погода и курсы обновляются по действию пользователя.
Выбор города также запускает его обновление; поиск города отправляет введённое название в геокодинг Open-Meteo.
В браузерной проверке успешно получены настоящие ответы **Open-Meteo и Frankfurter**.
Также проверены формулы, ввод и автосохранение заметок, демо-чат, локальный черновик письма, рисование и отмена, карточки памяти и продолжение таймера при переходах.
Главная и инструменты просмотрены на ширине 390 px, интерфейс помощника — на 768 px; на мобильном экране инструментов горизонтального переполнения не обнаружено.
В интерфейсе подписаны источник, дата наблюдений или время получения; сетевой сбой не маскируется под успешное обновление.
Сохранённый прогноз кэшируется отдельно для координат каждого города, а устаревшие данные получают соответствующую отметку.

Frankfurter v2 возвращает массив записей `{date, base, quote, rate}` и поддерживает RUB.
Портал использует blended-курсы из официальных источников; это не биржевые котировки в реальном времени и не обязательно отдельный курс ЦБ РФ.
Введённая в конвертер сумма вычисляется локально и не отправляется в API.
Платные, коммерческие и нагруженные сценарии требуют проверки действующих условий выбранного поставщика данных.

### ИИ и собственный API

По умолчанию чат показывает заранее подготовленные ответы с отметкой «Демо» и не вызывает модель.
В настройках можно указать базовый адрес OpenAI-совместимого API, имя модели и при необходимости свой ключ.
Поддерживаемый формат — `POST /chat/completions`, `stream: false`, ответ `choices[0].message.content`.
Если указан базовый адрес вида `https://your-api.example/v1`, путь `/chat/completions` добавляется автоматически.
Совместимость конкретной модели и доступность выбранного сервера необходимо проверять отдельно: **живой LLM в приёмке не подключался**.

Ключ находится только в памяти вкладки: он не записывается в `localStorage`, исходники или резервную копию.
После перезагрузки его нужно ввести заново; при смене origin API прежний ключ очищается.
Адрес сервера и имя модели сохраняются локально. Сообщения и введённый ключ отправляются именно на выбранный адрес.
Сервер должен разрешать origin портала через CORS; для внешнего API требуется HTTPS.
HTTP разрешён формой только для localhost/loopback, но фактический доступ зависит от ограничений браузера и настроек локального сервера.
Общий ключ, которым пользуются все посетители публичного сайта, должен храниться на серверной стороне, а не в HTML/JS.

### Почта, посылки и индексы

Gmail, Outlook и другие почтовые аккаунты **не подключены**. Ссылки открывают соответствующие почтовые сервисы.
Сохранение черновика не отправляет письмо. Демо-вложения и письма не являются данными настоящего аккаунта.
Для пользовательских посылок портал сохраняет номер и ссылку; он не запрашивает автоматический статус доставки.
Маршрут отправления и биржевые графики маркированы как демонстрационные; переключатели меняют именно пример визуализации.
Кнопки возле индексов открывают настоящие страницы инструментов на TradingView.

## Данные, сохранение и резервные копии

Личные записи сохраняются в `localStorage` с префиксом `ayyy:v1:`.
Это пространство конкретного origin в конкретном браузере: другой домен, профиль или устройство получит отдельные данные.
Облачной синхронизации, общего аккаунта и совместного редактирования в текущей версии нет.
Очистка данных сайта или недоступность браузерного хранилища влияет на сохранение; важные записи следует экспортировать.
Таймер использует время окончания сессии, но не обещает звуковое уведомление при закрытом браузере.

В настройках доступны «Экспорт» и «Восстановить основные данные».
Экспорт JSON включает сохранённые локальные ключи AYYY: в том числе заметки, чаты, черновики и настройки, если они присутствуют.
Секрет подключения LLM в экспорт не входит, поскольку не находится в браузерном хранилище.
Импорт проверяет и восстанавливает только **заметки, задачи, закладки, избранное, направления главной и посылки**.
Перед заменой этих разделов показывается подтверждение; другие локальные записи не заменяются.
Экспорт дополнительных записей не означает, что интерфейс импорта восстановит все настройки, рисунки, игровые состояния или историю сессий.
Отдельно можно скачать заметку в Markdown, разговор в TXT, закладки в JSON и рисунок в PNG.

## Исходники и сборка

Редактируемые исходники находятся в `src/`, а готовый для открытия и GitHub Pages документ — в корне `index.html`.
Никаких runtime-зависимостей от npm, внешних JavaScript-библиотек, шрифтов CDN или серверного фреймворка нет.
Рисунок маяка — локальный WebP с прозрачностью; луч, пиктограммы и графики — SVG, рисование — Canvas, интерактивность — обычный JavaScript.

| Файл в `src/` | Ответственность |
| --- | --- |
| `template.html` | Каркас документа, меню, верхняя панель, контейнер экранов и диалоги. |
| `style.css` | Общая палитра, типографика, компоненты, адаптивность и темы. |
| `core.js` | `window.AYYY`, маршрутизация, переключение оболочки, утилиты, SVG-иконки и перечень сервисов. |
| `tools.js` + `tools.css` | Восемь локальных инструментов. |
| `creative.js` + `creative.css` | Рисование и три игры. |
| `data.js` + `data.css` | Погода, геокодинг, валюты, конвертер и демо-индексы. |
| `productivity.js` + `productivity.css` | Заметки, задачи, закладки и таймер фокуса. |
| `pages.js` | Общий поиск, поисковые провайдеры и посылки. |
| `splash.js` + `splash.css` | Главная, каталог, акварельная оболочка, луч и выбор шести направлений. |
| `home-data.js` | Частичное обновление погодного и валютного виджетов главной. |
| `connected.js` | Чат, настройки собственного API и демонстрационная почта. |
| `boot.js` | Инициализация, настройки оформления, быстрый переход и резервные копии. |
| `build.py` | Объединение шаблона, CSS и JavaScript в HTML и копирование локальных assets; Python standard library. |

Из корня репозитория:

```bash
python3 src/build.py
```

По умолчанию результат записывается в корневой `index.html`.
При необходимости можно указать другой путь: `python3 src/build.py dist/index.html`.
Редактируйте исходники и пересобирайте документ: ручные изменения результата сборки будут перезаписаны.
Порядок модулей задаётся в `build.py`: `core`, `tools`, `creative`, `data`, `productivity`, `pages`, `connected`, `boot`.
Каждый экран регистрируется через `AYYY.register(id, {title, render, mount})`; возвращаемая из `mount` функция очищает его обработчики.
Для проверки синтаксиса отдельного модуля можно выполнить `node --check src/data.js`; Node не нужен для просмотра портала.

## Публикация на GitHub Pages

1. Разместите готовый `index.html` и папку `assets/` в корне репозитория (в этом репозитории они уже есть).
2. Добавьте рядом пустой файл `.nojekyll`, чтобы публиковать файлы без обработки Jekyll.
3. В `Settings → Pages` выберите `Deploy from a branch`, нужную ветку и `/(root)`.
4. Сохраните настройки и откройте URL, который покажет GitHub после публикации.

Для такого варианта npm-сборка и собственный workflow Actions не нужны.
Если редактируются исходники, выполните `python3 src/build.py` и закоммитьте обновлённый корневой `index.html` вместе с исходниками.
Можно отдельно настроить публикацию `dist/` через GitHub Actions; готового workflow в этой версии не требуется.

### Домен ayyy.*

Домен пока **не настроен**: нужно выбрать один конкретный принадлежащий вам адрес.
Запись `ayyy.*` описывает семейство доменов и не является значением для файла `CNAME`.
Для выбранного адреса настройте Custom domain в GitHub Pages и соответствующие DNS-записи у регистратора.
При публикации из ветки файл `CNAME` содержит ровно этот домен, без `https://` и без пути.
После проверки домена и выпуска сертификата включите HTTPS; точные DNS-значения берите из актуальной документации GitHub.
Личный некоммерческий портал соответствует назначению прототипа. При монетизации или превращении в коммерческий SaaS нужно пересмотреть условия GitHub Pages и API либо сменить хостинг.
